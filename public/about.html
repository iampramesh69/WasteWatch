PROJECT OVERVIEW

About WasteWatch.

A community reporting for tracking waste incidents and cleanup progress.

What problem does it solve?

One-time cleanups do not always stop waste from returning. WasteWatch creates a simple incident log so a community can track categories, locations, response status and repeated reports in one place.

＋

1. Report

Submit a category, date, location, description and optional photo. The API validates required fields and stores the report in SQLite.

✓

2. Respond

Search reports and update a report to Reported, In progress or Cleaned. Photo upload is limited to 5 MB.

⌖

3. Prevent

Group repeated location names and show a rule-based suggestion for human follow-up.

How the project is structured

Each layer has one job. The browser does not connect directly to the database.

Frontend

Separate HTML pages + CSS + JavaScript ES modules. Sends HTTP requests using fetch().

Backend API

Node.js + Express validates requests, accepts image uploads and exposes /api/reports routes.

Database + files

SQLite stores report records in data/wastewatch.sqlite; images are saved under uploads/.

AWS deployment path

This project is ready to run locally. AWS resources are not created automatically.

  1. For a first demonstration, deploy the Node app to an EC2 instance and keep the SQLite database and uploads on persistent storage.
  2. For a multi-user production app, move report records to Amazon RDS or DynamoDB and photos to a private Amazon S3 bucket.
  3. Add authentication/roles, HTTPS, backups, validation, rate limiting and an AWS budget before inviting public users.

Security limitation: this has no authentication or role permissions. Do not expose it publicly with real personal data until access control and deployment hardening are added.
